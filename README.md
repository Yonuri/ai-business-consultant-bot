# AI-консультант по базе знаний компании — Telegram-бот

Telegram-бот, который отвечает клиентам **только на основе документов и страниц сайта,
загруженных администратором**. Никаких выдуманных цен и условий: если ответа в базе знаний
нет, бот честно об этом говорит и предлагает позвать менеджера.

В комплекте — демо-документ стоматологической клиники «Дентал Люкс», чтобы проверить работу
сразу после запуска.

## Что умеет бот

**Клиентская часть**

- `/start` — приветствие и объяснение, чем бот может помочь.
- Вопрос текстом → бот ищет 5 самых релевантных фрагментов базы знаний и отвечает по ним.
- Внизу экрана всегда доступны две кнопки:
  - **🧹 Очистить историю диалога** — начинает разговор с чистого листа;
  - **🙋 Позвать менеджера** — принимает вопрос или контакт и пересылает заявку всем админам.
- В конце ответа — источник (название документа), чтобы было видно, откуда взят факт.
- Если информации в базе нет, бот не фантазирует: предлагает связаться с менеджером.

**Админ-панель (`/admin`, только для `ADMIN_IDS`)**

| Кнопка | Что делает |
| --- | --- |
| 📄 Добавить документ | Загрузка PDF / DOCX / TXT / MD, извлечение текста, нарезка на фрагменты, индексация |
| 🔗 Добавить ссылку (URL) | Парсинг страницы сайта (очистка от меню, скриптов, cookie-баннеров) и индексация |
| 📚 Управление базой знаний | Список источников с датой и числом фрагментов, удаление в один клик |
| 🧪 Тест режима клиента | Вопрос → ответ бота + найденные фрагменты с оценкой релевантности |
| 📊 Статистика | Пользователи, вопросы, источники, фрагменты, заявки менеджеру |

## Архитектура

```
Telegram ──► aiogram 3 ──► handlers (user / admin)
                                │
                                ├── ConsultantService ──► RagEngine (ChromaDB)
                                │            │                 └── эмбеддинги Gemini
                                │            └──► GeminiClient (generateContent)
                                │
                                ├── KnowledgeService ──► DocumentParser (PDF/DOCX/TXT/HTML)
                                │            └────────► SQLite (aiosqlite)
                                │
                                └── Database: пользователи, источники, история, статистика
```

**Ключевые решения**

- **Разделение хранилищ.** SQLite — «источник правды» об источниках, истории и статистике;
  ChromaDB — только векторы и текст фрагментов. Удаление источника затрагивает оба хранилища.
- **Честность ответа.** Системный промпт запрещает модели выдумывать факты. Если ответа нет,
  модель возвращает служебный маркер `[[NO_ANSWER]]`, и бот подставляет собственный вежливый
  отказ — так текст отказа не зависит от «настроения» модели.
- **Порог релевантности.** Фрагменты с косинусной близостью ниже `RAG_MIN_SIMILARITY`
  отбрасываются ещё до обращения к модели.
- **Отказоустойчивость.** Повторы с экспоненциальной задержкой на 429/5xx и сетевых ошибках;
  ошибки 4xx (неверный ключ, плохой запрос) не повторяются.
- **Безопасность URL.** Парсер отклоняет localhost, приватные и служебные адреса и проверяет
  **каждый** шаг цепочки редиректов — защита от SSRF.

## Быстрый старт

Требуется **Python 3.11+**.

```bash
# 1. Перейдите в каталог проекта
cd project1

# 2. Создайте виртуальное окружение
python -m venv .venv

# Windows:
.venv\Scripts\activate
# Linux/macOS:
source .venv/bin/activate

# 3. Установите зависимости
pip install -r requirements.txt

# 4. Создайте файл конфигурации
# Windows:
copy .env.example .env
# Linux/macOS:
cp .env.example .env

# 5. Откройте .env и заполните BOT_TOKEN, GEMINI_API_KEY, ADMIN_IDS
#    Без них бот не запустится и подскажет, что именно не заполнено

# 6. Запустите бота
python main.py
```

> Файл `.env` уже создан в проекте с заглушками. Если запустить бота, не заполнив
> обязательные переменные, он завершится с понятным сообщением, а не «молча повиснет»:

```
❌ Не удалось запустить бота: настройки заполнены неверно.

  • BOT_TOKEN выглядит как заглушка — вставьте токен от @BotFather
  • GEMINI_API_KEY выглядит как заглушка — вставьте настоящий ключ из Google AI Studio
  • ADMIN_IDS пуст — укажите свой Telegram ID (узнать: @userinfobot)
```

## Где взять ключи

### 1. Токен Telegram-бота

1. Откройте [@BotFather](https://t.me/BotFather) в Telegram.
2. Отправьте `/newbot`, придумайте имя и username (должен заканчиваться на `bot`).
3. Скопируйте токен вида `123456789:AAH...` в `BOT_TOKEN`.

### 2. Ключ Gemini API

1. Перейдите на [Google AI Studio](https://aistudio.google.com/app/apikey).
2. Войдите в аккаунт Google.
3. Нажмите **Create API key** (при первом обращении нужно принять условия использования).
4. Скопируйте ключ вида `AIzaSy...` в `GEMINI_API_KEY`.

> Бесплатного уровня достаточно для тестов и небольших объёмов. Для продакшена включите
> биллинг в Google Cloud — иначе возможны ограничения по запросам в минуту и в сутки.

### 3. Свой Telegram ID для `ADMIN_IDS`

1. Напишите боту [@userinfobot](https://t.me/userinfobot).
2. Он пришлёт ваш числовой `id`.
3. Укажите его в `ADMIN_IDS`. Несколько админов — через запятую: `123456789,987654321`.

## Первый запуск и проверка

1. Запустите `python main.py` — в консоли появится строка
   `Бот запущен: @your_bot (id=...)`.
2. В Telegram отправьте боту `/start`.
3. Отправьте `/admin` → **📄 Добавить документ** → прикрепите файл
   `sample_docs/clinic_knowledge.txt`.
4. Бот ответит: «Файл успешно загружен. Добавлено N фрагментов в базу знаний».
5. Проверьте поиск: **🧪 Тест режима клиента** → спросите «Сколько стоит имплантат?».
   Вы увидите ответ и найденные фрагменты с оценкой релевантности.
6. Напишите боту в клиентском режиме любой вопрос без `/admin`:

| Вопрос | Ожидаемое поведение |
| --- | --- |
| Сколько стоит лечение кариеса? | Ответ по прайсу + источник |
| Делаете ли вы МРТ головного мозга? | Отказ: в базе знаний нет такой услуги |
| Можно ли оплатить материнским капиталом? | Ответ из раздела «Частые вопросы» |
| Как записаться на приём? | Ответ из раздела «Запись на приём» |

## Запуск в Docker

```bash
cp .env.example .env      # заполните переменные
docker compose up -d --build
docker compose logs -f bot
```

Данные (SQLite и ChromaDB) сохраняются в каталог `./data` на хосте — база знаний
не потеряется при пересборке контейнера. Остановка: `docker compose down`.

## Как работает RAG

1. **Извлечение текста**
   - PDF — `pypdf`; DOCX — `python-docx` (включая таблицы); TXT/MD — чтение
     с автоопределением кодировки (UTF-8 / CP1251).
   - URL — `httpx` + `beautifulsoup4`: удаляются скрипты, стили, навигация, cookie-баннеры;
     приоритет отдаётся `<article>` / `<main>`.
2. **Нарезка на фрагменты** — 800 символов с перекрытием 150, по границам абзацев
   и предложений (`CHUNK_SIZE`, `CHUNK_OVERLAP`).
3. **Векторизация** — `text-embedding-004` через `google-genai`; векторы нормализуются,
   ChromaDB работает в косинусном пространстве.
4. **Поиск** — вопрос векторизуется с `task_type=RETRIEVAL_QUERY`, берутся топ-5 фрагментов
   (`RAG_TOP_K`) с порогом `RAG_MIN_SIMILARITY`.
5. **Генерация** — `gemini-2.5-flash` получает системный промпт, контекст и историю диалога
   (последние 8 сообщений) и отвечает только по контексту.

## Настройки

Все параметры — в `.env` (см. `.env.example` с комментариями).

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `BOT_TOKEN` | — | Токен бота от @BotFather |
| `GEMINI_API_KEY` | — | Ключ Google AI Studio |
| `ADMIN_IDS` | — | Telegram ID админов через запятую |
| `GEMINI_MODEL` | `gemini-2.5-flash` | Модель генерации |
| `EMBEDDING_MODEL` | `text-embedding-004` | Модель эмбеддингов |
| `EMBEDDING_DIM` | `768` | Размерность вектора |
| `GEMINI_TEMPERATURE` | `0.2` | Температура ответа |
| `GEMINI_THINKING_BUDGET` | `0` | 0 — без «размышлений» (быстрее), -1 — авто |
| `RAG_TOP_K` | `5` | Сколько фрагментов передавать модели |
| `RAG_MIN_SIMILARITY` | `0.2` | Порог отсечения нерелевантных фрагментов |
| `CHUNK_SIZE` / `CHUNK_OVERLAP` | `800` / `150` | Параметры нарезки |
| `HISTORY_LIMIT` | `8` | Сколько сообщений истории идёт в контекст |
| `QUESTIONS_PER_HOUR` | `40` | Лимит вопросов на пользователя в час |
| `MAX_DOCUMENT_BYTES` | `20971520` | Максимальный размер файла (20 МБ) |
| `LOG_LEVEL` | `INFO` | Уровень логирования |
| `HTTPS_PROXY` | пусто | Прокси для Gemini, если регион заблокирован |

### Если Gemini блокирует ваш регион

Google отвечает `400 FAILED_PRECONDITION: User location is not supported` на запросы
с российских IP. Telegram-часть при этом работает, но ответы на вопросы — нет.
Решение — прокси или VPN с выходом **не из России**.

```bash
# 1. Укажите прокси в .env (схему можно не писать)
HTTPS_PROXY=socks5://127.0.0.1:1080

# 2. Проверьте его перед запуском бота
python check_proxy.py
```

Скрипт `check_proxy.py` покажет, какая страна видна наружу, и проверят ли генерация
и эмбеддинги Gemini. При старте бот делает ту же проверку и пишет в лог
`✅ Gemini API доступен` либо причину отказа.

Подойдёт локальный клиент с SOCKS5 (Hiddify, Clash, v2ray, Nekoray) или платный
HTTP-прокси с авторизацией. Cloudflare WARP **не помогает**: он выходит из Москвы,
и Google блокирует его так же.

> Для SOCKS-прокси нужен пакет `socksio` — он уже включён в `requirements.txt`
> (`httpx[socks]`).

> ⚠️ **`EMBEDDING_DIM` нельзя менять на уже заполненной базе.** Если нужно — удалите каталог
> `data/chroma` и загрузите документы заново: векторы другой размерности в один индекс не лягут.

## Как адаптировать под свой бизнес

1. **Тексты** — `bot/texts.py`: название компании, приветствие, телефон, описания кнопок.
2. **Промпт** — `SYSTEM_PROMPT` там же: тон общения, правила, запреты.
3. **База знаний** — загрузите свои документы через `/admin`, демо-файл удалите
   в разделе «Управление базой знаний».

Логику менять не нужно.

## Частые проблемы

| Симптом | Причина и решение |
| --- | --- |
| `❌ Не удалось запустить бота: настройки заполнены неверно` | В `.env` остались заглушки. Сообщение перечисляет, какие именно переменные нужно заполнить |
| `ValidationError` про `ADMIN_IDS` | В `ADMIN_IDS` не число: нужен числовой Telegram ID, а не username |
| Бот молчит на вопросы | База знаний пуста. Загрузите документ через `/admin` |
| «Текст в документе не распознан» | Скан PDF без текстового слоя. Прогоните файл через OCR (OCRmyPDF, Adobe Acrobat) и загрузите снова |
| «Gemini API недоступен из вашего региона» | Google блокирует IP вашей страны. Укажите `HTTPS_PROXY` и проверьте: `python check_proxy.py` |
| «Gemini API недоступен» | Неверный `GEMINI_API_KEY`, закончилась квота или нет доступа к модели. Проверьте ключ в AI Studio |
| Бот отвечает «нет информации», хотя она есть | Понизьте `RAG_MIN_SIMILARITY` (например, до `0.1`) и проверьте в «Тест режима клиента», какие фрагменты находятся |
| Заявки менеджеру не приходят | Админ ни разу не открыл чат с ботом или заблокировал его. Нажмите `/start` в чате с ботом |
| Ссылка не индексируется | Сайт отдаёт контент через JavaScript или блокирует ботов. Загрузите документ вручную |
| «Ссылки на внутренние адреса запрещены» | Сработала SSRF-защита. Это ожидаемо для `localhost` и приватных сетей |
| Ошибка размерности при старте | Меняли `EMBEDDING_DIM` на заполненной базе. Верните прежнее значение или пересоберите `data/chroma` |

## Безопасность

- **Токены только в `.env`**, файл в `.gitignore` и `.dockerignore` — не попадёт
  ни в репозиторий, ни в образ.
- **Админка** закрыта фильтром по `ADMIN_IDS`; на `/admin` от не-админа бот вежливо отказывает.
- **HTML-экранирование** пользовательского текста в заявках: клиент не сможет «сломать»
  сообщение админу разметкой.
- **SSRF-защита** в парсере URL: запрещены localhost, приватные, loopback и link-local адреса;
  проверяется каждый редирект; размер ответа ограничен.
- **Ограничения нагрузки**: лимит размера файла и страницы, лимит длины вопроса,
  rate limit на пользователя.
- **Контейнер работает не от root** (`USER appuser` в `Dockerfile`).
- **Логи** не содержат токенов и содержимого ключей.

Перед публикацией в продакшен включите биллинг Gemini, настройте ротацию ключей
и резервное копирование каталога `data/`.
